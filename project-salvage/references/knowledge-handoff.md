# 交付一份文档，再建议沉淀去向

默认成果是一份 Markdown：完整项目复盘，或一次问题的简短经验文档。文档本身就能阅读、转发和放进用户已有知识系统，不要求维护专门的经验库。

## 先完成文档

完整复盘按[报告说明](retrospective-report.md)组织；单次经验整理可用[经验文档模板](../assets/experience-note.md)。写清实际问题、当前做法、证据、改变判断的原因，以及可复用对象的入口与使用条件。

简单问题用几段话写清，不扩写成项目级长报告。影响选择的具体缺失集中说明一次；其他段落直接陈述事实与行动，不反复追加适用范围或免责尾句。

优先更新用户已经保存的相关文档。没有约定位置时，完整报告可放项目 `docs/retrospectives/project-salvage.md`，单次整理放 `docs/retrospectives/<主题>.md`；源项目只读则用当前获准输出目录。只要求在回复交付或明确禁止写文件时，输出可直接保存的 Markdown。

整理任务以一份文档为交付单位。除非用户另有要求，不拆分为多条经验、不新建 INDEX.md、experiences 或证据目录，也不自动创建 `knowledge/`。仅查旧方案或指定直接合并时，按该范围交付，不另生成报告。安装的 skill 目录只放能力文件，用户资料放在用户指定的位置。

文档内保留理解结论必需的事实，避免只留下某个平台聊天链接。同一资料目录中的链接优先用相对路径；技术入口集中在文末。摘录必要事实即可，不复制整段聊天或无关个人内容。

## 给出具体去向建议

根据本次内容选择有价值的去向，写明建议放什么、为什么、拟新增或修改哪段、当前是否已执行。没有合适去向时，保留本次文档即可。

| 建议去向 | 适合什么内容 | 怎样建议 |
| --- | --- | --- |
| 用户已有知识库 | 跨项目方法、决策理由、可重复使用的排查办法 | 给出拟合并的简短段落和相关现有笔记；没指定知识库时只给建议 |
| 项目文档 | 本项目的现状、操作流程、模块用法和验证要求 | 指向实际 README、开发说明或其他已有文档，给出具体修改 |
| 项目规则 | 会影响本项目 agent 行动的短要求 | 检查现有 AGENTS.md、CLAUDE.md、GEMINI.md 等，给可执行短规则 |
| 全局指令 | 用户明确的长期要求，或独立情境中反复出现的稳定偏好 | 给有依据的具体提案，按[全局偏好流程](global-preferences.md)批准后写入 |

反复执行的流程还可建议做成 skill，具体可判对错的情境可建议转成测试。已有代码默认保留原物入口与依赖说明，不因一份报告自动抽取代码。

## 用户自行处理，或授权协助沉淀

先给可直接采用的文案，让用户决定是否沉淀、去哪里；这不影响先完成本次文档。用户也可以自行复制、调整和保存。

用户明确要求“帮我合并到这个知识库／项目文档”时，直接处理已授权的目标，不对普通段落逐条要求再次确认。没有指定目标且会影响实际去向时，再询问该目标；其余分析和文档先完成。授权保存一份报告，不等于授权修改其他文档。

写入前读取相关原文，按已有结构处理，不新建一套平行目录。相同事实已存在就不改；有新依据时补入原处，推翻旧做法时更新当前建议，并用短段说明变化原因。已有判断仍有用的部分和用户手工内容保持原样。

全局指令以具体方案和条目获批为条件。批准后只改相应条目，相关原文发生冲突时先修订方案。知识库写入授权不扩大为全局指令授权。

## 完成交代

回读文档和实际修改，检查链接、重复及未授权改动。回复区分“文档已交付”“仅建议用户自行采纳”“已合并到指定文档”“全局提案待批准／已写入”。同一材料再次处理没有增量时，不改文件或更新时间。

如果用户已维护旧版 skill 生成的经验资料，按现有普通 Markdown 使用，用户指定后可以合并；不自动删除、迁移或另建目录。更新或卸载 skill 也不处理用户已有知识资料。
